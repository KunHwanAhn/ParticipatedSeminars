# 통합테스트로 보다 안전한 웹프런트엔드 서비스 제공하기
- 이호빈님 / C트랙

## 프론트엔드 통합테스트?
- 서버와 함께하는 테스트?
- 내부 함수들의 연결 관계 테스트?
- 코어 웹 프로트엔드에서 담당하는 영역
  - 주문
  - 결제
  - 회원

## 분기처리가 제일 쉬웠어요
- 기존에 있는 코드 수정 보다는 새로운 기능을 추가하는 방식으로 개발
- 많은 분기처리로 인해서 유지보수 성이 낮아짐
- 영향범위 최소화 VS 코드 유지보수성? => 테스트를 작성하자

## 테스트의 유형
- 단위 테스트
- 통합 테스트
- E2E 테스트

## 단위 테스트
- 개별 모듈, 컴포넌트의 검증
- 코트의 논리적 오류 검증
- 장점: 빠른 속도 / 단순함 / 독립적
- 단점: 검증 가능한 영역이 제한적

## 통합 테스트
- 모듈 간의 상호작용 검증
- 서버 응답에 따른 동작 확인
- 장점: 실제 시나리오와 유사
- 단점: 테스트 설정과 유지의 어려움

## E2E 테스트
- 사용자가 애플리케이션을 사용하는 환경을 재현해서 전체 시나리오 검증
- 장점: 최종 사용자 경험을 검증
- 단점: 느린 속도 / 의존성 높음

> E2E와 같이 고수준의 테스트를 진행할 수록 유저 경험을 보장하기는 쉽지만, 유지보수가 어려워짐

## 과거의 테스트 코드
- 논리적 오류가 없는가?
- 내부 상태가 잘 업데이트 되는가?
- 이벤트 핸들러가 잘 호출되는가?
- 서비스는 Application
- 검증 대상은: 저수준의 모듈 단위 테스트

> 주수준 단위 테스트 만으로는 검증을 만족할 수 없다

## 발생 가능한 문제점
- 모듈의 연동 과정에서 문제가 발생할 수 있다
- 서버 상태, 전역 상태의 변화를 ㄷ롱반하는 시나리오 검증이 필요하다
- 코드 수정에 따른 영향 범위를 충분히 파악하기 어렵다

## 통합 테스트
- 함수, 컴포넌트가 함께 작동하는 방식을 검증

### 모듈 연동 결함 발견
- 딘위 테스트 검증을 잘했더라도, 실제 사용하는 곳에서 잘못 사용하면 이슈가 될 수 있다.
```tsx
const CartList = () => {
  // 단위 테스트 검증 완료!
  const { itemList, updateItem, deleteItem } = useFoo();

  return (
    <div>
      {itemList.map((item) => {
        // 컴포넌트 단위 테스트 검증 완료!
        <CartItem
          item={item}
          // 단위 테스트 검증은 각각 잘 됐지만, 활용하는 부분에서 잘못 사용한 경우
          onUpdate={deleteItem} // <- onUpdate에 deleteItem을
          onDelete={updateItem} // <- onDelete에 updateItem을
        />
      })}
    </div>
  )
}
```

#### 요소 검색 API
- getByRole('button', { name: '추가' }) - '추가'라고 써진 버튼 <- 유저 관점에서 판단하는 것과 유사한 방식 권장
- getByText('추가') - '추가'라는 텍스트가 있는 요소
- getByTestId('add-button') - 'add-button'이라는 Test ID를 가진 요소

### 통합 테스트를 통해 서버 통신 시나리오 검증
- 실제 서버에 요청한다면?
  - 불필요한 트래픽 발생
  - 네트워크, 서버 상황 의존성
  - 다양한 응답 케이스 테스트 어려움
- getBy - 요소를 찾을 수 없으면 에러
- findBy - 비동기 / 요소를 찾을 때까지 대기
- queryBy - 요소가 없으면 null 반환

#### MSW (Mock Service Worker)
- 브라우저, Node 환경 API 모킹 라이브러리
- Jest 등의 테스팅 라이브러리와 같이 사용할 수 있도록 지원하고 있음

### 페이지 수준의 복잡한 시나리오 테스트
- 컴포넌트 간의 기능 점검도 가능
- 범위가 커질수록 테스트를 하기 위한 추가 설정이 점점 커진다는 단점이 있음

### 코드 수정의 영향 범위 파악
- 변경된 모듈의 영향을 받는 다른 정책 및 동선 검증 가능

### 통합 테스트의 장점
- 신뢰도 향상
  - 개발 신뢰도 향상
  - 핵심 동작 검증 집중
- 정책 파악 용이
  - 코드 리뷰 원활 - 테스트 코드의 description을 작성하다보니 의도를 파악하기가 더 쉬워짐
  - 온보딩 원활
- 개발자 경험 향상
  - 빠른 피드백
  - 코드 품질 향상

### 통합 테스트의 단점
- 주입해야 하는 의존성이 많아짐
